# 7.6.31 pre-release evidence

## Scope

Split the flat `evolution-pack` private distribution tier into 4 sub-tiers
by content kind, at the user's direction, following an architecture
discussion prompted by a queued marketing-strategy candidate with no
existing skill owner. Purely organizational: no skill's actual behavior,
routing, or public/private visibility changes.

## Background

A candidate mined from a past game project's press kit (a spokesmodel/
influencer promotional-narrative pattern) had no clear existing skill
owner — `indie-game-product-evolution` explicitly excludes marketing-domain
execution from its scope. The user asked whether to build a dedicated
marketing-operations skill family. Discussion covered:

1. Whether `developing-skills`' methodology (RED/GREEN, lifecycle stages,
   routing/behavior case design) is domain-generic enough to reuse for a
   different domain — confirmed yes, and already established as such by the
   2026-08-15 `developing-skills`/`developing-eval` split (that decision
   explicitly called `developing-skills` "analogous to Anthropic's own
   skill-creator").
2. Whether a fully separate repository/plugin was the right container —
   rejected: it would require either duplicating the evolution/eval tooling
   (`manage_skill.py`, `validate_pack.py`, `run_runtime_evals.py`, etc.) or
   generalizing them to accept a target-repo argument, an ongoing
   maintenance cost with no immediate benefit given only one candidate
   exists so far.
3. The chosen shape: same repository, same canonical `.agents/skills/`
   source, same evolution tooling (zero duplication, matching the already-
   proven `private-plugin` symlink pattern), but the private tier split into
   sub-tiers so future marketing/art content has a home distinct from both
   the game-product family and the self-referential meta-tooling.
4. User asked whether the split should be 3-way; landed on 4 sub-tiers
   (`private-meta`, `private-game`, `private-operation`, `private-art`)
   because the meta-tooling/game distinction already existed implicitly in
   this ledger's own prior reasoning (see the 2026-08-14 entries), and
   `config/skill-domain-catalog.json` already had both `marketing-dev` and
   `art-dev` product domains defined with planned-but-unbuilt skills.
5. User asked to avoid the name `private-core` for the meta-tooling
   sub-tier (would collide with the existing public `core` tier name);
   renamed to `private-meta`.

## Changes

- `config/skill-distribution.json`: `tiers` replaced (`evolution-pack`
  removed, `private-meta`/`private-game`/`private-operation`/`private-art`
  added); `skills` map reclassified 1:1 (`developing-eval`,
  `local-runtime-eval-debugging`, `runtime-evaluation-engineering` ->
  `private-meta`; the 7 game skills -> `private-game`); new decision-ledger
  entry recording the full reasoning above.
- `scripts/export_public_bundle.py`, `scripts/validate_pack.py`,
  `scripts/validate_plugins.py`, `scripts/validate_skill_portability.py`,
  `scripts/sync_private_codex_plugin.py`: every `tier == "evolution-pack"`
  check replaced with `tier != "core"`, so this split (and any future
  private sub-tier) needed no further script changes.
- `config/skill-domain-catalog.json`: `default_distribution_for_product_domains`
  and each category's `default_distribution` updated
  (`art-dev` -> `private-art`, `marketing-dev` -> `private-operation`,
  remaining game-related domains -> `private-game`).
- `README.md`, `INSTALL.md`, `docs/SKILL_TAXONOMY.md`,
  `docs/CLOUDBOX_SKILLS_DEVELOPMENT_MAP.md`, `private-plugin/README.md`:
  updated live references to the old flat tier name; also fixed a stale
  "21 skills" count in `private-plugin/README.md` to the correct 31.
  Historical documents under `docs/releases/` and `docs/evolution/`
  deliberately left unchanged (point-in-time records, not live state).
- `private-plugin/codex-skills/` regenerated via
  `scripts/sync_private_codex_plugin.py` (content identical — the skills it
  mirrors did not change, only their tier label did).
- `SKILL_MANIFEST.json`: regenerated by `scripts/validate_pack.py`.
- Version bump `7.6.30` -> `7.6.31` (patch — internal reorganization,
  no new public capability, no behavior change for any skill).

## Disclosed limitations

- `private-operation` and `private-art` are empty reserved categories. No
  skill exists in either yet; `private-operation`'s first candidate
  (spokesmodel/influencer marketing pattern) stays queued in
  `.local/eval-inbox/candidates/` pending batch review, same as the other
  10 queued candidates.
- A dedicated router skill for a future marketing/operations family, and a
  tier-scoped `SKILL_MANIFEST.json` generator (so that router would not load
  all 21 core engineering skills' descriptions), are both still undesigned
  and unbuilt — explicitly deferred until there is enough real evidence
  (3-5 candidates) to define trigger/non-trigger boundaries, not built
  speculatively on the current 1 thin candidate.
- `agent-development-process`, `document-governance`, and
  `teach-while-building` remain un-reviewed since `7.5.0`, now blocking a
  clean minor version bump for a third consecutive release.
