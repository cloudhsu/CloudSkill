## Considered and shelved: generalizing game-domain evolution-pack Skills

Investigated whether to generalize `game-quality-and-release-gates`,
`legacy-game-product-archaeology`, `cloudbox-game-migration`, and
`native-ios-game-rewrite` into domain-agnostic verb-shaped Skills (the
"known structural gap" noted in `docs/SKILL_ROUTING_PLAYBOOK.md`: no
archaeology/migration/release-readiness Skill outside games).

A read-only content check found all four Skills' `SKILL.md` text and eval
cases already free of product-identifying detail (empty `references/`/
`assets/` directories on all four; `legacy-game-product-archaeology`'s
`LGPA-BEH-004` case is explicitly labeled a de-identified archetype;
`native-ios-game-rewrite`'s cases are grounded in real legacy products per
its own `lifecycle.json` notes but the eval prompt text itself is already
abstracted to mechanic-level description with no product/vendor/company
name). So de-identification was not the blocking concern.

**Shelved anyway, on cost/benefit grounds, not a sanitization risk**: the
user's near-term roadmap centers on indie game development specifically.
Generalizing would add real, measured router-composition risk (this same
release's own `CAD-NEG-01`/`CAD-NEG-02` noise demonstrates the mechanism —
two independently-correct skills producing 3/21 strict-gate misses purely
from adjacent-skill selection noise) for a benefit (serving a future
non-game project) that is not part of the stated near-term plan, while the
existing game-specific Skills already have no unmet need for the work
ahead. Consistent with this repo's own `AGENTS.md` principle ("do not
introduce a pattern or methodology without identifying the pressure it
addresses") and this session's own precedent for `codebase-architecture-discovery`
(created only because a real 64-file audit had already happened, not
speculatively). No files changed for this item; the assessment is a
report, not a code change. Revisit only if a real non-game project
actually creates the need.
