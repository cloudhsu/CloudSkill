# CloudBox Skills 7.8.0 release

Covers PRs #107–111 plus one directly-pushed follow-up commit
(`957551e`, CI-verified). Full detail in `CHANGELOG.md`'s 7.8.0 entry.

## Summary

- `using-cloudbox-skills` full real-execution pass (26/26 authored
  routing/behavior cases) surfaced a genuine self-reference gap, then
  an independent review found the original diagnosis itself was wrong
  (a case-authoring CSV column misread, never checked against the real
  deterministic grader). Reverted the wrong fix, corrected the case
  data, removed a second pre-existing self-reference hole in the
  router's own instructions, and re-verified in both directions with
  live re-runs. Closes Vikunja `cloudbox-skills #17` by dissolution.
- `rejected_skills` hallucination fix in the shared runtime harness's
  contract-repair step: previously discarded all mechanical repair
  whenever any skill ID anywhere was unknown, even in a field that
  does not gate execution, destroying real evidence on 4 confirmed
  occurrences across 3 Skills. Closes Vikunja `cloudbox-skills #18`.
- `document-governance` and `game-quality-and-release-gates` first
  real execution evidence: all remaining authored cases run, several
  real findings disclosed rather than swept into a clean pass.
- Cross-provider hook path fix: `.claude/settings.json`,
  `.codex/hooks.json`, `.gemini/settings.json` no longer break when a
  hook-triggering tool call's working directory drifts from the
  repository root.
- `scripts/validate_runtime_evals.py` now validates every
  `evals/runtime/cases/*.json` file sharing the routing-decision-
  contract shape, not just `canary.json` -- the exact gap that let the
  `using-cloudbox-skills` case-authoring bug reach real model quota
  undetected. Found and fixed one real pre-existing inconsistency in
  `cad-routing.json` along the way.
- 13 new formal behavior cases from a reviewed Eval Inbox batch across
  12 Skills (deduplicated, sensitive-content re-scanned, ownership-
  mapped, human-reviewed before conversion).
- `AGENTS.md` documentation correction: interaction-capture triggers
  (`整理成正向案例`/`整理成負向案例`) correctly attributed to
  `developing-eval`, not `developing-skills`.

## Validation evidence

- `python3 scripts/run_all_checks.py`: PASS at the release tip.
- Every routing/behavior fix in this release was verified by a live
  re-run against the real model (`--provider claude`) and, for
  `using-cloudbox-skills`'s corrected cases, by the real deterministic
  grader (`scripts/grade_runtime_evals.py`) -- not assumed from the
  diff or read from raw output by eye.
- PRs #107–111 individually CI-verified (GitHub Actions
  `Validate CloudSkill`) before merge; the directly-pushed follow-up
  commit `957551e` is also CI-verified on `main`.

## Limits

- The 13 new behavior cases from the Eval Inbox batch are structural/
  schema evidence only -- real model execution against them is
  `NOT RUN` yet.
- The broader Vikunja `cloudbox-skills #7` statistical-rigor backlog
  remains open for ~29 of 42 Skills (zero or minimal real execution
  evidence).
- The case-file validator extension does not yet cover
  `behavior-rubrics.json` and its rubric-schema siblings (a different,
  un-generalized shape) -- tracked as a follow-up, not silently
  skipped.
- No hardware, device, platform-install, or production-deployment
  claims.
