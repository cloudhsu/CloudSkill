# CloudBox 6.5.0 pre-release evidence

Minor release. Promotes five interaction-derived Eval Inbox candidates into
committed Skill decision-rule text and behavior cases, across four Skills. No
new Skill, no schema change, no bundle-format change. `runtime-evaluation-engineering`
remains `stage=experimental`; the other three affected Skills remain `stage=active`.

## Source evidence

All five candidates originated from live-interaction and project-history
mining passes 7-11 against the Skytech Bento lunch-ordering project
(external, non-CloudSkill repository), imported on this machine via the
disconnected-session export/import path (`export_eval_candidate.py` ->
`import_eval_candidates.py`) and staged in `.local/eval-inbox/manual-review/`.

Before promotion, all candidates from those passes (14 total) were put
through empirical baseline-vs-candidate sub-agent comparisons against the
real target Claude Code runtime -- not reasoning about a hypothetical. Each
sub-agent pair was isolated with scoped tool access and an explicit
"answer with a written plan only" framing where a real artifact was not the
goal, per the containment discipline this release itself adds as
`RTE-BEH-010`. Two candidates had a wording-level gap (overgeneralization,
internal contradiction) surfaced by their first comparison; both closed in
one revision round and were re-tested against the identical scenario before
being included here (a third revised candidate, `permission-allowlist-hygiene`,
converged with the baseline's independently-designed three-tier approach and
is included as `CAG-BEH-007`). Nine sibling candidates showed no material
behavioral delta after a required harder-scenario retest, or were superseded
by one of the five promoted here, and were moved to
`.local/eval-inbox/rejected/` with the comparison evidence recorded in each
file's `review_notes` -- not deleted.

## Verification

- `python scripts/manage_skill.py refresh --all` -- refreshed 19 lifecycle
  records; the four affected Skills' `behavior_case_ids` now include the new
  case IDs.
- `python scripts/manage_skill.py audit --check` -- clean; no orphaned or
  missing case references.
- `python scripts/run_all_checks.py` -- `validate_descriptions.py` (19
  Skills), `validate_behavior_evals.py` (142 behavior case contracts across
  19 Skills, including the 5 new cases), and `validate_skill_lifecycle.py`
  all pass. The suite's only failures are the pre-existing, unrelated
  Windows-local gaps already documented in the 6.4.1 release evidence (no
  working WSL `bash` on this machine, so the `install.sh`-invoking
  sub-scenarios in `validate_interaction_capture.py` fail identically
  before and after this change) and the intentional
  `missing-version-fixture` self-test line. CI (`validate-cloudskill.yml`,
  `ubuntu-latest`) runs the same suite on a real POSIX host where that gap
  does not exist.
- Behavior execution against the new SKILL.md/reference text specifically
  (as opposed to the candidate's own pre-promotion wording) has not been
  re-run; the eval-loop evidence in the table above was gathered against
  each candidate's staged wording before it was folded into the committed
  Skill reference files. This is a `MANUAL_REQUIRED` gap for future review,
  consistent with `developing-skills`' own rule that structural validation
  is not a behavior pass.

## Compatibility

No bundle format, schema, or lifecycle-stage change. `v6.4.1` remains a
valid rollback target; rolling back drops the five new behavior cases and
their reference-file content but requires no data migration in either
direction.
