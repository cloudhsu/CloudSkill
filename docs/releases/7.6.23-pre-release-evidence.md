# CloudBox 7.6.23 pre-release evidence

Date: 2026-08-16 (Asia/Taipei)

## Scope and privacy boundary

This increment adds a generalized external project-management synchronization
Skill. The committed Skill and Eval cases contain no real endpoint, credential,
backlog, task, account, email, or remote identifier. Local provider profiles,
SecretStore entries, and mapping data remain outside Git.

## Skill and classification

| Skill | Capability | Product domain | Distribution | Lifecycle |
|---|---|---|---|---|
| `project-management-sync` | `integration-dev` | none | public `core` | active |

Supporting capabilities are `architecture-dev` and `governance-dev`. The
Skill's provider-neutral core is separate from versioned Vikunja, OpenProject,
Redmine, and future adapters. OS-specific credential APIs are hidden behind a
SecretStore boundary.

## RED and correction

The first candidate behavior run completed routing and behavior execution but
produced an unnecessary non-placeholder identity in one generated report. The
sanitized failure was: `report contained a real email/account identifier`.
This was a behavior/privacy RED, not a provider mutation.

The correction added an explicit final privacy audit, prohibited repeating an
ambient identity even when explaining redaction, required reserved placeholders,
and added a deterministic rubric penalty for non-placeholder email patterns.

## Explicit non-claims

No OpenProject, Redmine, or future Ubuntu provider-backed write was executed in
this release. The Skill does not claim that an unknown provider version is
compatible; it requires discovery, adapter support, and read-only fallback.
