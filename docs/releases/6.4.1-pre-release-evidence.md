# CloudBox 6.4.1 pre-release evidence

Patch release. Fixes a Windows-only bundle-corruption defect in
`export_eval_candidate.py`, found via the 6.4.0 version-compatibility
self-test in `validate_interaction_capture.py`. No lifecycle, routing, or
behavior-case content changed; no new Skill, no schema change, no bundle
format change.

## Defect

`package_outbox()` built `payload_hashes` manifest keys with
`str(path.relative_to(outbox))`. On Windows this yields backslash-separated
paths (e.g. `manual-review\INT-....json`). `zipfile.write()` independently
normalizes the archive member name (`arcname`) to forward slashes on every
OS regardless of host, so the manifest's declared key never matched the
actual archive member it described.

`import_eval_candidates.py`'s structural check --
`set(names) != {"manifest.json", *manifest["payload_hashes"].keys()}` --
then raised, was caught by the surrounding exception handler, and the entire
archive was reported `skipped` as an invalid zip. Every candidate inside was
silently discarded, not partially imported; no data was corrupted, but
Windows-exported candidates never reached the Inbox.

Scope: `export_eval_candidate.py` on Windows, only when invoked *without*
`--no-zip`. The `--no-zip` path (write the candidate JSON only, no
packaging) and `capture_eval_candidate.py` (same-machine capture, no zip
step at all) were unaffected on every OS.

## Fix

One-line change: `path.relative_to(outbox).as_posix()` instead of
`str(path.relative_to(outbox))`, matching zipfile's own separator
normalization on every OS.

## Verification

- Reproduced the corruption pre-fix on a Windows machine: built a candidate
  zip with the unpatched code, confirmed `ZipFile.namelist()` returned
  `manual-review/INT-....json` (forward slash) while
  `manifest["payload_hashes"]` had the key `manual-review\INT-....json`
  (backslash), and confirmed the real `import_eval_candidates.py --dry-run`
  reported the archive `skipped` with "not a valid zip archive".
- Applied the fix, rebuilt the identical scenario, confirmed
  `namelist()` and `payload_hashes` keys now match exactly
  (`set(names) == {"manifest.json", *payload_hashes.keys()}`), and the same
  dry-run now reports a clean `manual_review=1` with no skip/unsupported
  count.
- `PYTHONDONTWRITEBYTECODE=1 python scripts/run_all_checks.py` on the same
  Windows machine: the previously-crashing `validate_interaction_capture.py`
  self-test now passes and prints "Validated full and config-only setup,
  ... the disconnected-session export/import round trip, ...". The suite's
  only remaining failures are a pre-existing, unrelated gap (this machine
  has no working WSL `bash`, so the `install.sh`-invoking sub-scenarios
  fail identically before and after this change) and the intentional
  `missing-version-fixture` self-test line -- neither caused or affected by
  this change.
- CI (`validate-cloudskill.yml`, `ubuntu-latest`) runs `run_all_checks.py`
  on a real POSIX host where the WSL gap does not exist, so the main-push
  and tag-push runs for this release are expected to be fully clean; their
  run URLs are recorded in the post-release record once available.

## Compatibility

No bundle format, schema, or lifecycle change. `v6.4.0` remains a valid
rollback target; this patch is a strict bugfix with no migration required
in either direction.
