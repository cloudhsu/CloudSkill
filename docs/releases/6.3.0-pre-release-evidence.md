# CloudBox 6.3.0 pre-release evidence

CloudBox 6.3.0 keeps Eval exchange explicitly manual and deterministic. It
withdraws the unreleased controlled-tool prototype and fixes the portable
bundle name to
`<project>-<host>-<agent>-<YYYYMMDDTHHMMSSZ>-<bundle-id8>.zip`.

The importer requires the filename to match the versioned manifest, scans all
ZIPs directly under the private Inbox `imports/` directory, deduplicates within
one batch, retains unsupported and malformed input for inspection, and never
calls a model or modifies formal Skills, Evals, or Git state.

## Verification

- Focused export/import validation covers persisted project and agent aliases,
  filename/manifest equality, a four-archive mixed batch, duplicate content,
  unsupported routing, malformed retention, and no provider dependency.
- The complete deterministic suite passed repeatedly before version
  synchronization. A final exact-tip run is required after this document and
  all version surfaces are committed.
- Independent review of the manual-only source found no High issue. Its one
  Medium test-coverage finding was corrected with the mixed-batch fixture and
  rerun before release preparation.
- Release review then found same-name evidence overwrite and missing ZIP
  resource bounds; both were corrected with retained-target naming and bounded
  archive metadata checks. A later review found intra-archive partial
  publication and member-path batch-abort paths; import now plans the entire
  archive before publication, avoids `extractall()`, bounds member paths and
  special entries, and contains expected ZIP read/decompression failures per
  archive. Final review also found untrusted candidate IDs could influence the
  output path; publication now uses a local content-derived basename and an
  explicit queue-containment check. These review failures are correction
  evidence, not release PASS; final exact-tip review remains required.

## Compatibility and rollback

Bundle format remains 2.0. Existing correctly named version-2 bundles remain
supported. A renamed bundle is deliberately classified unsupported because its
transport identity no longer matches its manifest. Unsupported and malformed
archives are retained rather than deleted. Rollback uses immutable `v6.2.0`;
no migration is required because the removed controlled automation was never
released.
