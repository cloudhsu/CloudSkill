## Classification evidence (minor bump)

Per `docs/history/RELEASES.md`'s versioning policy, a minor bump requires
a new active/publicly-usable skill or capability, or a backward-compatible
behavior extension to an existing one. This release qualifies on both
counts against **public** Skills specifically (not merely the private
tier):

- 6 public Skills (`framework-design`, `equipment-control-architecture`,
  `equipment-domain-modeling`, `codebase-architecture-discovery`,
  `code-review`, `safe-incremental-refactoring`) each gained a new
  behavior case from #103's equipment-porting candidates.
- The bundled-hook mechanism (used by public Skills
  `coding-agent-git-discipline`, `coding-agent-project-governance`,
  `document-governance`, `project-management-sync`) gained Windows-native
  coverage and unified logging.
- `using-cloudbox-skills` (public) gained a real routing-defect fix.

The new `technical-case-content-generation` Skill and its follow-up
candidate merge are `private-operation` tier only and do not themselves
justify the public-facing minor classification -- the public-Skill
behavior extensions above do, independently.

## Hook / governance evidence

- Hook logging change (`36b611f`) is disclosed purely additive: an
  earlier draft that changed `validate-push-readiness.sh`'s fail-open
  behavior on checker crash was reverted per explicit user instruction to
  preserve current block/allow semantics exactly.
- Root cause of the original Windows Codex hook failures (confirmed by
  the user on the actual second machine) is documented in `INSTALL.md`:
  the 3 directly-wired hooks are not managed by
  `install_skill_hooks.py`, so there is no installer step rewriting this
  repository's own committed `settings.json` to the `.ps1` variant on
  Windows -- a contributor must swap locally and must not commit that
  swap back to git.
