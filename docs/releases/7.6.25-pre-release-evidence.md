Date: 2026-08-17 (Asia/Taipei)

## Scope

governance, an internal-logic audit of every script in `scripts/`, a real
consolidation refactor, and one new Core Skill. Full detail already lives in
dedicated documents; this file is the release-gate summary and index, not a
duplicate of that detail.

### 4. New Core Skill: `codebase-architecture-discovery`

Distilled from the audit above as real, observed source material (not a
hypothetical): a staged, checkpointed batch-discovery method for surveying
an unfamiliar codebase and empirically verifying duplicated logic before
refactoring it. Paired with `safe-incremental-refactoring` the same way
`legacy-game-product-archaeology` is paired with
`gameplay-core-modernization` (discovery-precedes-execution). Owner-search
performed per `developing-skills` before creating a new Skill rather than
extending `safe-incremental-refactoring` (assumes the slice is already
known) or `architecture-review` (a single-decision comparison between named
options) — reasoning recorded in `config/skill-domain-catalog.json`'s
decision ledger.

Promoted `draft` -> `experimental` on real, executed RED/GREEN evidence
(Claude Code CLI 2.1.233, `sonnet` alias, `repeat=1`, single-attempt — not
yet release-grade repeat evidence):

| Layer | GREEN (skill present) | RED (skill removed from `SKILL_MANIFEST.json`, restored + diff-verified byte-identical after) |
|---|---:|---:|
| Routing (5 cases) | 1.0 (5/5) | 0.2 (1/5) |
| Behavior (2 graded cases) | 100.0/100 both | not run (disclosed scope limit) |

The real finding: without the skill, an unfamiliar 60-file
subsystem/no-known-slice prompt (`CAD-01`) misrouted to
`safe-incremental-refactoring` — a genuine premature-execution-skill
selection, exactly the failure mode this Skill exists to intercept. One RED
case (`CAD-02`) hit a Claude CLI structured-output retry exhaustion,
disclosed and counted as `BLOCKED` rather than excluded. Full narrative:
`docs/evolution/2026-08-17-codebase-architecture-discovery-first-pass-evidence.md`.

Not yet `active`: needs repeat-count evidence (`repeat=3`) and a broader
adjacent-regression sweep beyond the 3 NEG cases already run once, per
`developing-skills/references/skill-lifecycle-standard.md`'s stage table.
Tracked as this release's immediate follow-up.

## Validation status

- `scripts/run_all_checks.py`: PASS at the exact release tip —
  `All CloudSkill checks passed.`
- GitHub Actions `Validate CloudSkill` (push, main): PASS on every commit in
  this increment, most recently run
  [32033967366](https://github.com/cloudhsu/cloudbox-skills/actions/runs/32033967366)
  against `69478fa` (the tip immediately before this version-bump commit).
- `CloudBox Evolution Source Sync` (scheduled workflow): failing on every
  scheduled run since at least 2026-08-14, unrelated to this release. Root
  cause confirmed via `gh run view --log-failed`: the repository has no
  `EVOLUTION_SOURCE_URL` / `EVOLUTION_EXCHANGE_URL` / `EVOLUTION_SOURCE_ID`
  secrets configured (`gh secret list` returns empty), so the job's own
  `test -n` preflight fails before any sync logic runs. This is a
  pre-existing, secrets-configuration gap, not a code regression, and is not
  a release gate for the same reason project-history background-sync
  tooling is explicitly out of the deterministic check suite. Left
  unresolved by this release; not addressed here because there is no
  evidence a real private Eval Exchange source is meant to be connected in
  this environment.
- No provider-backed mutation, credential data, project/task identifier, or
  private product identifier is included in these public Core changes.
