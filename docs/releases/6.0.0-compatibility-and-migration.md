# CloudBox 6.0.0 compatibility and migration

## Major-version boundary

CloudBox 6.0 makes evidence and authority contracts externally enforceable.
The major boundary is contributor/runtime-tooling compatibility, not a claim
that every Skill changed behavior.

- Host-level task continuity is represented by versioned schemas under
  `evals/agent/`, independent of Skill routing.
- Consequential action requests, authority envelopes, parent state, provider
  identity, raw output, and cost evidence have explicit contracts.
- Multi-model panels require four distinct family/role cells, unique worker
  outputs, blinded evidence, canonical returned-model identity, degraded-panel
  truth, and provider-specific cost reporting.
- Lifecycle audit rejects a shipped Skill that remains `unreleased` and a Skill
  whose declared two-feature-release review trigger has expired.

These changes can break custom Eval consumers, validators, or release scripts
that assume only Skill-scoped cases, accept self-asserted semantic outcomes,
average provider scores, overwrite panel output, or treat lifecycle metadata as
decorative.

## Preserved compatibility

- The 19 canonical Skill IDs and existing routing contracts are unchanged.
- No global task-continuity instruction or Skill behavior was changed: all ten
  hosted baseline cases passed before Task 5.
- Existing Codex and Claude plugin package shapes remain supported.
- Runtime provider results remain separate; Ollama is not required for this
  release increment.

## Migration

1. Consume `evals/agent/task-continuity.schema.json` and the Task 3 execution
   result schema rather than projecting host continuity into routing CSV rows.
2. Treat provider `outcomes` as untrusted; mechanically grade state/actions and
   use independent semantic adjudication.
3. Give every panel worker a unique output path and record requested versus
   canonical returned model identity.
4. Report a blocked worker as a degraded panel, never a completed 2x2.
5. Keep provider/model/cost-kind totals separate and never derive quality from
   spend.
6. Correct lifecycle metadata from repository/release evidence; do not promote
   stages or invent behavior execution through mechanical refresh.

## Rollback

The verified prior release is `v5.8.0`. Roll back by reinstalling its published
plugin artifact or checking out that tag. Task-continuity and panel evidence
created under 6.0 should be retained for audit but ignored by 5.8 tooling; do not
down-convert it into misleading Skill-scoped PASS records.

## Exclusions

- Host/plugin reload is not implied by package smoke installation.
- Static fixtures do not prove model behavior.
- The 6.0 boundary does not claim whole-corpus live Behavior coverage for all
  Skills.
