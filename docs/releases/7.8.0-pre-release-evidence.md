## Classification evidence (minor bump)

Per `docs/history/RELEASES.md`'s versioning policy, a minor bump
requires a new active/publicly-usable skill or capability, or a
backward-compatible behavior extension to an existing one, against
**public** Skills specifically. This release qualifies on multiple
independent counts:

- `using-cloudbox-skills` (public): a real routing-defect fix
  (self-reference gap, corrected twice -- see Verification-before-action
  evidence below) and a real shared-harness fix
  (`rejected_skills` hallucination in `deterministic_contract_repair`).
- 9 of the 13 Eval Inbox batch additions landed on public Skills:
  `architecture-review`, `coding-agent-git-discipline`,
  `coding-agent-project-governance`, `document-governance`,
  `equipment-control-architecture`, `equipment-domain-modeling`,
  `safe-incremental-refactoring`, `software-quality-iso25010`,
  `teach-while-building` each gained a new behavior case (the other 4
  landed on private-tier `cluster-tool-simulator-development`,
  `developing-eval`, `wph-equipment-simulator-development`).
- `document-governance` (public) and `game-quality-and-release-gates`
  (public) both gained their first full real-execution pass.
- The cross-provider hook-path fix and the case-file validator
  extension are cross-cutting infrastructure used by every Skill's
  own eval/hook tooling, public and private alike.

## Verification-before-action evidence

- `using-cloudbox-skills`'s self-reference fix was corrected TWICE in
  the same investigation, each time verified by a live re-run before
  being trusted, not assumed: the first fix (commit `5f9d873`) was
  itself found wrong by an independent Opus 5 review that ran the real
  deterministic grader (`scripts/grade_runtime_evals.py`) against the
  "verified" records and found `overall_pass_rate=0.0`; the corrected
  fix (`4359aac`) was re-verified in both directions with fresh live
  model calls (the originally-failing cases now pass, unrelated
  passing cases stay unaffected).
- The `rejected_skills` hallucination fix was unit-verified against
  the real historical failure payload (the hallucinated ID is
  correctly dropped, `final_errors` empty) plus a safety-boundary test
  (an invalid `primary_skill` still correctly blocks all repair,
  unchanged) before being trusted.
- The 13 Eval Inbox batch candidates were deduplicated
  (`scripts/detect_candidate_similarity.py`, 0 pairs scored >= 0.28),
  manually re-scanned for identifying detail (all had
  `sanitization.status: MANUAL_REQUIRED` -- exported without a
  reachable private terms file; clean on manual read of all 13), and
  ownership-mapped by actual skill-domain fit rather than the source
  candidate's field order, before conversion.
