## Scope

(private) to `core` (public) at the user's explicit direction, after an

## Sanitization review

Checked against the exact bar already applied to
`semiconductor-equipment-domain-knowledge`/`equipment-control-architecture`/
`equipment-domain-modeling`: "no specific company, project, customer,
recipe, or safety-limit identifiers." Confirmed no company, employer, or
product name was ever present in this skill. Found and fixed two real
gaps, plus one minor one:

1. `references/implementation-map.md`'s "Current reference modules"
   section named literal file paths from one specific C# codebase
   (`WphSimulator.Rewrite/SimulationModel.cs` and 10 similar entries).
   Rewritten as "Typical module responsibilities" describing each module's
   role generically, matching how the other core-tier equipment skills
   describe architecture without naming real files.
2. `references/domain-baseline.md`'s "Timing classification" table and
   `SKILL.md` step 6 stated concrete calibrated machine values (specific CT
   Z-motion seconds, specific slot/cassette-count/PM-process-time values)
   labeled "confirmed machine input." A cross-check confirmed the existing
   core-tier equipment skills carry zero concrete numeric machine values at
   all (`grep` for numeric timing/quantity patterns across their reference
   files returned nothing). Rewrote both files to keep the identical
   classification-table shape and confirmed/provisional discipline (the
   actual reusable teaching content) while replacing every literal measured
   value with an explicit placeholder (`*measure on machine*`,
   `*machine-specific count*`).
3. `references/evidence-cases.md` referenced a literal screenshot filename
   (`error7.png`) from the source project's bug tracker — genericized to
   "a supplied screenshot."
