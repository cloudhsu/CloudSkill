The release fixes the Windows-only `export_eval_candidate.py` bundle-corruption
defect reported in [#19](https://github.com/cloudhsu/CloudSkill/issues/19) and
fixed in [#20](https://github.com/cloudhsu/CloudSkill/pull/20): manifest
`payload_hashes` keys built with `str(path.relative_to(outbox))` did not match
the forward-slash-normalized archive member names `zipfile.write()` actually
produces on Windows, so `import_eval_candidates.py` rejected the whole archive
as invalid and silently discarded every candidate inside it. Fixed with
`Path.as_posix()`. Found via the 6.4.0 version-compatibility self-test in
`validate_interaction_capture.py`.

No lifecycle, routing, behavior-case, or bundle-format change. Rollback uses
immutable `v6.4.0`; `v6.4.0`-exported candidates from non-Windows hosts, and
any `--no-zip` exports from any host, were never affected by the defect this
patch fixes.
