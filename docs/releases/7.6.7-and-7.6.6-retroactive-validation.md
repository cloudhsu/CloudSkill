# Retroactive skill-creator validation: 7.6.6 and 7.6.7

## Scope

Two skill changes shipped earlier on 2026-08-15 via manual editing, never
behaviorally tested with a with/without comparison, retroactively validated
with Anthropic's `skill-creator` eval-loop following the same session's
`safe-incremental-refactoring` v7.6.18 methodology:

- `agent-development-process` v7.6.7: "Fixing a Gap: Harness Component vs.
  Memory" (`references/tool-and-state-design.md`).
- `developing-skills` v7.6.6: "Release truth" tag+Release-is-part-of-the-
  release-step paragraph (`references/skill-lifecycle-standard.md`).

## Method

For each skill, created a `without_skill` baseline by stripping the target
section (and its `SKILL.md` cross-reference) back to its pre-change wording,
then ran 3 realistic prompts per skill (a positive-application case, a
deliberate counterexample, and an adversarial variant targeting the shipped
content's own referenced incident) through paired current-skill vs.
stripped-baseline subagents. Full data: `agent-development-process-validation-workspace/benchmark.json`
and `developing-skills-validation-workspace/benchmark.json` (gitignored,
machine-local; this document is the retained evidence).

## Result

- Assertion pass rate: 12/12 (100%) in BOTH configurations, both skills, all
  6 prompts. No assertion-level behavioral delta on Claude Sonnet 5.
- Root cause: the pre-existing rules each section formalizes already
  generalize a strong model to the same conclusion —
  `agent-development-process`'s tool-design rules ("enforce authorization in
  code, not only in instructions") and pre-7.6.7 "do not close a recurring
  issue only by changing prompt text" line; `developing-skills`'s
  pre-existing "Release truth" evidence-class list (tag/push reported
  separately from CI/structural/behavior).
- Qualitative (non-assertion) difference: on `release-commit-not-done`, the
  with-skill response gave five itemized concrete steps including an
  explicit `gh release list` confirmation; the baseline reached the same
  conclusion with less procedural specificity — plausibly more load-bearing
  on a weaker model than Sonnet 5.
- This is the third consecutive no-assertion-delta result on Sonnet 5 across
  this session's skill-creator validations (following
  `safe-incremental-refactoring` v7.6.18's iteration 1). Recorded as a
  general expectation for incremental additions to this repo's already-mature
  skills, not a reason to stop making them: explicit, auditable, named
  guidance still has value (weaker-model robustness, human legibility) even
  without a measured behavioral delta on the strongest available model.

## Decision

No revision made to either section — content kept as shipped in v7.6.6 /
v7.6.7. No version bump: this document records validation evidence for
already-released content, not a content change.
