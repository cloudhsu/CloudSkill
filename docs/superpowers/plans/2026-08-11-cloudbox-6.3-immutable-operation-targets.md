# CloudBox 6.3 Immutable Operation Targets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace mutable remote/inbox action identity with contract-v2 immutable fetch-ref and bundle-archive targets across prepare, execute, retry, and reconciliation.

**Architecture:** A read-only `tool prepare` phase resolves capability arguments into a bounded canonical `operation_targets` object. The lifecycle owner authorizes that exact digest; the broker persists it and adapters execute/reconcile only those items. Manual inbox import remains dynamic and unchanged.

**Tech Stack:** Python 3.7-compatible standard library, JSON Schema, Git CLI, repository-native executable validators.

## Global Constraints

- No mutation occurs during target preparation.
- Invocation contract is `2.0`; durable action schema is version 2.
- Target digests use canonical sorted JSON and are recomputed at every trust boundary.
- Fetch targets contain exact ref/object IDs and no endpoint value.
- Bundle targets contain only root-relative paths, SHA-256, and byte size.
- Late remote changes and late archives never alter an existing action.
- V1 non-terminal checkpoints are retained and blocked, never silently migrated.
- Manual Eval bundle import remains supported without requiring controlled-action targets.
- No arbitrary shell, live GitHub mutation, polling, or implicit prune behavior.
- Add RED before production changes and run the same case GREEN afterward.
- Update handoff and change history whenever the open failure layer changes.
