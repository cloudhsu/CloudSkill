# CloudBox 6.1 Git-first Evolution Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a versioned manual candidate exchange, portable token-free Git source synchronization, and evidence-tested architecture decision elicitation without weakening existing private-data or release controls.

**Architecture:** Keep the public repository as the control plane and a user-owned private Exchange as candidate/provenance storage. Build one stdlib-first CLI contract that local machines, GitHub Actions, self-hosted CI, and a later NAS runner can invoke. Reuse the existing capture/import sanitization contract and keep model/evolution/release authority outside background synchronization.

**Tech Stack:** Python 3.11 standard library, Git CLI, JSON/JSON Schema, GitHub Actions YAML, existing CloudSkill behavior/runtime Eval harness.

## Global Constraints

- Target version is `6.1.0`; do not change release version surfaces until the final release gate.
- NAS folder watching and ten-minute filesystem scans are deferred to 6.2.
- Background synchronization must make zero model calls and cannot edit Skills, commit, push CloudSkill, create PRs, tags, or releases.
- URLs, credentials, private paths, raw repositories, and private candidates must never enter the public repository, logs, errors, prompts, bundles, or public evidence.
- Source credentials are read-only and separate from the private Exchange write credential.
- Manual import remains available through the new format; legacy unimported bundles are unsupported, retained, and never automatically deleted.
- Every materially changed Skill requires literal RED baseline evidence before instruction edits and the same case must turn GREEN before release claims.
