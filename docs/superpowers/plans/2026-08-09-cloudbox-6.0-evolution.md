# CloudBox 6.0 Evidence-Gated Evolution Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and release a defensible CloudBox 6.0 contract for task continuity, evidence-driven Skill evolution, hosted 2x2 evaluation, lifecycle truth, and two-phase release evidence.

**Architecture:** Add a host-level task-continuity Eval contract beside the existing Skill-scoped Behavior Evals, then use its preserved baseline to justify only the smallest global and specialist instruction changes. Add a provider-neutral semantic-panel ledger and bounded Claude fallback without averaging provider scores. Treat lifecycle/version/release artifacts as authoritative contracts and release only after targeted RED/GREEN, bounded full verification, CI, install smoke, and explicit compatibility evidence.

**Tech Stack:** Python 3 standard library, JSON Schema contracts, Markdown Skills and governance, Codex CLI, Claude Code CLI, Git/GitHub Actions, existing CloudSkill validators and plugin packagers.

## Global Constraints

- No production instruction or Skill change before a witnessed failing baseline case.
- No Ollama/local-model execution.
- One repository writer and one release coordinator; independent agents remain read-only unless assigned one isolated task.
- Provider results remain separate and are never averaged into one quality score.
- Safety, authority, privacy, unsupported-claim, and evidence-lineage findings are vetoes requiring adjudication.
- A failed or degraded planned 2x2 cannot be reported as a completed panel.
- The byte-identical earlier GPT packet is unavailable; new packets must be frozen and hashed before use.
- A 6.0 version is permitted only when the final compatibility review identifies a coherent public contract boundary; otherwise propose a real compatible 5.9.0 release.
- Push, PR, merge, annotated tag, and GitHub Release are authorized only after all release gates pass.
- `.local/` stores raw provider evidence and costs; credentials, account identifiers, and raw authentication output are excluded.
